# IAC 后端拆分

用户确认服务名为 `iac-platform`；原 IQC 保留 `iqc-platform`。只新增独立后端，现有管理前端切换 API，不建设新前端或 worker。

## 职责和复用

IAC 独占智能体、不可变版本、模型连接配置、MCP、Skill 及版本、测试聊天和会话历史。IQC 保留质检规则、导入素材、方案、任务、评分、结果和基于任务的 Agent 效果统计。IQC 消费 IAC 服务发布的资产与版本，不跨库查询，不复制智能体持久化模型或维护双写。

已检查 IQC agent/modelprofile/mcp/skill 模块、OpenSabre Framework starters、组织/治理服务及知识 Wiki。框架提供认证、服务发现、RPC、持久化、迁移、审计、限流和治理注册，但没有独立智能体管理服务；将现有应用实现迁出，不向框架或基础服务添加领域能力。

通用模型/MCP 调用由 IAC 提供；IQC 的质检提示词、脱敏、结构化输出验证、候选/标签语义、重试及业务计量仍属于 IQC。IQC 通过内部调用执行冻结快照，防止复制凭据解析和 MCP 连接实现。接口失败明确阻止创建/执行，不回退本地旧表。

## 数据与接口

IAC 使用独立 `iac_platform` 数据库及 `iac_` 表前缀；保留迁移后的业务 ID、版本号、审批状态、配置内容、时间和归属。新库 baseline 只含七张相关表及索引，不带生产数据。历史数据导入是显式迁移工具，不放进初始化脚本。原 IQC 已发布迁移保持不可变；切换后不读写旧管理表，也不自动 DROP。

管理 API 使用 `/api/iac/config`，独立 `iac:*` 资源编码。原管理前端仅迁移这些 API，IQC 效果报表保留原 API。内部服务协议支持按 ID/版本读取、校验实时资产、冻结资产及使用已冻结快照调用模型。

## 发布和验证

本轮本地实现和验证。发布前需要独立审批具体共享配置清单：数据库账号与 schema、Nacos 配置/内部令牌受众、网关 IAC 路由、组织菜单及资源角色映射。不得以本地开发授权替代基础服务变更审批。

按备份、创建新库、暂停全部旧管理写入与受影响任务并等待在途请求结束、导入并逐表核对、启动 IAC、升级全部 IQC 实例、发布原管理前端、真实身份读写验证的顺序切换。原数据保留供核对，回滚不得让两个后端同时写不同数据副本。
